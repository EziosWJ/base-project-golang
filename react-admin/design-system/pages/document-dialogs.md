# 单据弹窗（详情与确认）

`DocumentSummary`、`DocumentItems`、`DocumentDisclosure`、`DocumentOperationRecords` 与 `DetailDialog`／`FormDialog` 的 `documentLayout` 组成同一套单据阅读层级：**详情表达已发生，确认表达将发生**。金额、影响、权限、快照与提交恢复由调用方提供，这些组件只负责展示与容器。

## 使用规则

- `documentLayout` 是可选开关，默认关闭。未开启时 `DetailDialog`／`FormDialog` 的尺寸、关闭策略与既有系统表单完全一致；普通资料编辑和短确认继续用默认布局。
- 开启后桌面宽度上限 1100px、视口高度上限 90dvh，头部与底部固定、正文独立滚动，小于 640px 使用全屏。不要在正文里再套固定高度的纵向滚动框。
- 信息顺序为：固定头部（身份、对象、日期、中文状态）→ 概览（金额、行数、影响）→ 本单明细 → 常显补充（备注、错误、取消原因）→ 可折叠辅助（送货资料、来源、关联单据、操作记录）→ 固定底部操作。
- 辅助分区默认折叠并保留摘要；错误、取消原因与关键警示必须默认可见，不能只藏在折叠区。
- 明细表以商品名称为主行，编码／型号／规格为辅行；数量附单位，成交单价与金额右对齐并使用等值定宽数字。不同单位不合计，空辅助值省略。
- 详情按行保留备注换行；空值显示 `—`，不编造数据。加载失败与空数据区分表达。
- 确认窗口在提交中禁用关闭、遮罩与重复提交；失败或版本变化后锁定确认按钮并改成「请刷新后重新核对」一类文案，由调用方决定何时解除。

## 示例与验收

- 示例页：页面示例 → 单据弹窗 Demo（`src/pages/examples/document-dialog-demo.tsx`，路由 `/examples/document-dialog`）。同一份内存数据并排演示详情与过账确认，含长单切换与模拟提交失败。
- 浏览器验收入口：`node tests/document-dialog.mjs`。其中组件级夹具同时回归未启用 `documentLayout` 的既有弹窗尺寸与关闭策略。
