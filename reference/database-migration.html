数据库 Migration 速查

代码版本 N → migration 文件 N → 执行到数据库 → 数据库记录已执行版本
Schema
数据库的结构：有哪些表、字段、索引、约束。
Migration
一次可版本化的 Schema 变更脚本，例如“创建 sys_user 表”或“给用户表增加邮箱列”。
Goose
执行 migration 并记录已执行版本的工具。它不会猜测表结构，而是按 Git 中的文件顺序运行。
为什么不用 AutoMigrate
AutoMigrate 让 ORM 根据代码猜测并修改表；它不提供清晰、可审查的历史记录，不适合作为生产数据库版本管理。

本项目的例子

首次部署：Goose 创建用户、角色、菜单、会话等表，并写入内置管理员数据。以后新增 auth_session 的字段，不改旧文件，而是新增下一号 migration。

一句话：Migration 是“数据库的 Git 提交历史”，保证开发、测试和生产最终使用同一份表结构。
